# Remaining release gates

These gates are not release approval. Batch 003 added bounded local PostgreSQL operations and recovery capabilities described below, with local synthetic-data evidence. Public Apache-2.0 alpha source and a passing Linux CI baseline are recorded in the release checklist. This is not a supported production release, hosted deployment, independent security review or readiness finding.

## Remaining work

| Ticket | Remaining scope | Acceptance / evidence still required |
|---|---|---|
| SEN-208A | Maintained interactive identity and MFA | Choose an IdP using residency, license, and runtime evidence; test login/logout, recovery, revocation, and MFA. Keep custom password systems out. |
| SEN-208B | Workspace membership and roles | Derive identity and workspace on the server for every API, job, export, and object operation; define admin/analyst/viewer/service boundaries; add cross-user and cross-workspace negative tests. |
| SEN-208C | Privacy lifecycle and service abuse bounds | Add subject-level data inventory, redaction/export/deletion with backup-expiry coordination, a reviewed retention schedule, physical capacity monitoring, service-level backpressure, idempotency for non-idempotent writes, and distributed rate limits. Event ingestion already deduplicates by source and event ID; logical quotas and manual retention do not complete these controls. |
| SEN-208D | Attributable audit and operational recovery | Add individual attribution, denied access/export audit where appropriate, externally anchored audit retention, independent scheduled/offsite backups, key escrow and rotation ownership, recurring measured restore drills and recovery objectives, monitoring, and incident ownership. Current mutation audit and manual local backup are narrower controls. |
| SEN-209A | Collection and normalized schema | Select one maintained collector; document source contract, parser failures, health and lag; keep synthetic fixtures licensed and separate. No collector is implemented by Batch 003. |
| SEN-209B | SIEM data-plane benchmark | Compare PostgreSQL with OpenSearch or ClickHouse using the same licensed synthetic workloads; measure sustained/burst ingest, retained bytes, p95 queries/detection, queue loss, and restore cost. Data-plane choice remains open. |
| SEN-209C | Detection engineering lifecycle | Batch005 adds versioned authored metadata, protected catalog, persisted revision evidence, positive/negative/missing-field fixtures and a manual review/rollback procedure. Remaining: historical registry, time-window correlation and late-event handling, suppressions/false-positive workflow, representative validation and exercised deployment rollback. |
| SEN-210 | Public release supply chain | Apache-2.0 public alpha source, contribution/private disclosure policy, notices/SBOM, Linux CI, CodeQL high/critical gate and protected main are implemented. Remaining: supported release policy, signed artifacts/provenance, recurring review/triage ownership and reviewed dependency updates. Source publication is not a production release. |
| SEN-211 | UI/component debt | Batch004 consolidates scoped console CSS and improves native controls/themes with automated and manual accessibility evidence. Continue splitting large console feature modules and extend coverage to the private workspace and full assistive-technology matrix. Make no bundle improvement claim without measurements. |
| SEN-212 | Independent security, privacy, and deployment review | Produce requirement-level ASVS 5.0 evidence, threat-model abuse cases, a scoped independent assessment, and qualified review of POPIA, residency, and government procurement requirements before any real-data hosted offering. |

Use a restricted synthetic-data pilot while these gates remain open. The local implementation does not establish feature parity, legal compliance, or readiness for multi-user or hosted real telemetry.
